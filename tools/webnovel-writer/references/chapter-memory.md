# 章节记忆系统

## 设计原理

AI 写长篇的核心痛点：写到第 5 章时，第 1 章的设定已经"遗忘"——表现为角色性格漂移、能力忽高忽低、埋的线索不回收、章节因果链断裂。

**解法：** 每章通过质量审核后，生成一个结构化的"记忆快照"。下一章生成时，将全局状态 + 最近 3 章记忆注入上下文。

---

## 记忆文件结构

文件：`memory/novel-memory.md`（由 AI 自动创建和维护）

### 第一部分：全局运行状态（始终在上下文中）

```markdown
# 全局运行状态（第 N 章结束后更新）

## 当前时间线
- 故事内时间：第 X 天
- 距离开篇：X 天

## 主角状态卡
- 姓名：
- 当前修为/等级：
- 当前身份/地位：
- 当前目标：
- 当前困境：
- 持有重要物品：
- 已知金手指/能力：______（已暴露）/______（未暴露给他人）

## 关键角色状态（不超过 5 人）
| 角色 | 身份 | 对主角态度 | 当前状态 | 最近一次出场 |
|------|------|-----------|---------|------------|
| | | | | 第 N 章 |

## 活跃情节线程
| 线程 | 类型 | 状态 | 预计回收章 |
|------|------|------|-----------|
| | 主线/支线/线索 | 进行中/已解决/暂停 | 第 X 章 |

## 本章因果链接
因：第 N-1 章 [事件]
→ 第 N 章 [事件]  
→ 推向：第 N+1 章 [预期事件]
```

### 第二部分：逐章记忆（上一章 + 最近 3 章完整保留，其余压缩）

## 记忆维护规则

### 每章完成后（阶段 4 通过后）

1. AI 生成本章"记忆快照"（第二部分格式）
2. AI 更新"全局运行状态"（第一部分）
3. 人类快速扫一眼，确认无错误（30 秒即可，不需要逐字审核）

### 上下文注入规则

生成第 N 章时，注入到 AI 上下文的内容：

| 内容 | 是否注入 |
|------|---------|
| 全局运行状态 | 始终注入 |
| 第 N-1 章记忆 | 始终注入 |
| 第 N-2、N-3 章记忆 | 注入（如存在） |
| 第 N-4 章及更早 | 不注入（信息已压缩到全局状态中） |
| 章节大纲（第 N 章） | 始终注入 |
| 写作规则摘要 | 始终注入（反 AI 味规则要点） |

### 回收记忆（需要查更早章节时）

如当前章节需要回收第 5 章埋的线索，AI 通过搜索 `memory/novel-memory.md` 中的"新埋线索"字段找到对应条目。

---

## 为什么 3 章窗口？

- **1 章不够**：因果链可能跨 2-3 章才形成闭环
- **太多浪费上下文**：3 章具体记忆 + 全局压缩状态，足以覆盖 95% 的连续性需求
- **超过 3 章的线索**：全局运行状态的"活跃情节线程"表会追踪长线

---

## 人类审核点（新增）

阶段 4 审核通过后，增加一步：

**记忆审核（30 秒）：**
- [ ] 主角状态卡是否正确？（等级、物品、目标）
- [ ] 新埋的线索是否记上了？
- [ ] 角色关系变化是否记上了？
- [ ] 有没有重要事件遗漏？

通过后，锁定本记忆，进入下一章规划。
